# Noctalia Wallpaper Assets & Configuration

Research findings for the Noctalia wallpaper pipeline. Gathered from the live
`ishtar` host (the only graphical NixOS machine with wallpapers in its home dirs)
and the repo Nix config. Last checked: 2026-07-26.

## Asset directories (live host: ishtar)

| User   | Path                          | File count | Formats            |
|--------|-------------------------------|-----------:|--------------------|
| root   | `/root/Pictures/Wallpapers`   |         17 | 8 jpg, 9 png       |
| shika  | `/home/shika/Pictures/Wallpapers` |      7 | 4 jpg, 3 png |

Note: there is **no** `~/.local/share/backgrounds` or `~/Pictures/Wallpapers`
symlink managed by the repo. The directories above are plain user data, not
Nix-provisioned (nothing in the repo references `Wallpapers`/`Pictures`/`backgrounds`).

## File naming patterns

- **root** — `wallhaven-<hexid>.<ext>` (e.g. `wallhaven-0q5q87.jpg`,
  `wallhaven-1jdky1.png`). Sourced from wallhaven.cc.
- **shika** — `wp<digits>-<subject>-wallpapers.<ext>` (e.g.
  `wp1924815-kurumi-tokisaki-wallpapers.jpg`). Sourced from getwallpapers.com /
  wallpaper-engine style dumps.

Both are flat single-directory collections. No sub-albums, no index file, no
manifest.

## Rotation / schedule: NONE exists

Verified three independent ways:

1. **systemd** — no user or system timers matching `wallpaper|backdrop|noctalia|
   rotation`.
2. **repo** — no wallpaper daemon is declared anywhere: no `swww`, `wallust`,
   `hyprpaper`, `waypaper`, `wpaperd`, `variety`, or `feh` in any `*.nix`.
3. **Noctalia binary** — `noctalia msg --help` enumerates no rotation/slideshow
   subcommand, and `strings` on the v5 binary surface no `rotation`/`slideshow`/
   `next-wallpaper`/`wallpaper-interval` tokens.

Conclusion: the current setup is a **static single wallpaper** applied by the
compositor / desktop, not a rotating slideshow. To add rotation a wallpaper
daemon + systemd timer (or a Noctalia plugin) would have to be introduced.

## Noctalia configuration (repo-owned)

Single source of truth: `modules/home/graphical.nix` → `programs.noctalia.settings`.

Relevant blocks:

```
backdrop = {
  enabled = true;
  blur_intensity = 0.5;   # 0.0 = none, 1.0 = max
  tint_intensity = 0.3;   # 0.0 = none, 1.0 = opaque
};
theme = {
  mode = "auto";          # follows day/night schedule
  source = "wallpaper";   # M3 palette derived FROM wallpaper
};
```

Important semantics: `theme.source = "wallpaper"` means Noctalia **derives its
color palette (Material 3) from the current wallpaper** — it is NOT a wallpaper
rotator and does not set/manage the wallpaper itself. `backdrop` only controls
the blur/tint behind the bar.

### Who this applies to

`modules/home/graphical.nix` is imported by exactly **one** user module:
`modules/nixos/users/shika.nix`. So `source = "wallpaper"` is live only for the
`shika` user.

The `root` user has **no Home Manager config in this repo**. Its live
`~/.config/noctalia/config.toml` therefore reads `source = "builtin"` (Catppuccin)
and is not generated by the machines repo — it comes from a separate/earlier
provisioning. This is the reason `root`'s live config diverges from `graphical.nix`.

### Live config evidence (ishtar)

`shika` (`/home/shika/.config/noctalia/config.toml`):

```toml
[backdrop]
blur_intensity = 0.5
enabled = true
tint_intensity = 0.3

[theme]

```

```toml
[shell]

[theme]

```

## Notes for downstream (rotation work)

- Assets live only on the live host under `~/Pictures/Wallpapers`; they are not
  in git. A rotation feature must decide: keep them user-side, or vendor a curated
  set into the repo (e.g. `modules/home/graphical.nix` via `home.file`).
- If rotation is wanted, the minimal path is a wallpaper daemon (swww is the
  common Niri-compatible choice) driven by a systemd user timer — Noctalia v5
  itself offers no slideshow primitive.
- `theme.source = "wallpaper"` will keep re-deriving palette from whichever image
  the daemon sets, so palette refresh is automatic once the daemon swaps images.
